## Database and compatibility

- Additive `migrations/0011_merchandise_catalog.sql` and its PostgreSQL counterpart. No ALTER/DROP/DELETE/reseed of old rows. Duplicate-safe inserts preserve subsequent owner edits.
- `node scripts/seed-merchandise.mjs` regenerates only the checked-in migration and ten placeholder SVGs; it never connects to any database. Review diffs before using it. `node scripts/convert-postgres-migrations.mjs` generates the PostgreSQL counterpart.
- Existing product/quote contracts are reused. For these ten categories, the existing material-option field represents a variant/size (shoe sizes, clothing sizes or specifications-to-confirm). Colors are unconfirmed by default. Server checks reject unlisted options.
- Existing required legacy dimension columns retain compatibility defaults of 20/20/10 in seed records. **These are not product measurements.** Merchandise pages, forms and private inquiry views hide furniture dimensions and show specifications-to-confirm; furniture measurements and validation remain intact. API consumers must not treat these placeholder fields as merchandise specifications. A future dedicated technical-specification/SKU/stock-ledger schema is not implemented here.
- Master Control reuses product editing, starting-price history, availability status, archive, private suppliers/cost comparison and customer inquiry follow-up. Mark an item available only after verifying actual inventory/supplier information. No stock reservations or automatic quantity deduction is claimed for this quotation-only site.
