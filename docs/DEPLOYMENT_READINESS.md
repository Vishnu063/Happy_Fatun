# Controlled preview remediation — 4 November 2026 IST

**Decisions: repository verification GO once exact-candidate push CI is successful; hosted controlled preview NO-GO; public commercial launch NO-GO.** No hosted URL/deployed revision is verified. This task fixes repository release controls and proves isolated PostgreSQL restoration; it does not bypass provider protection, register/merge a default-branch workflow, modify provider settings/secrets/DNS/data, or deploy to production.

## Source and root causes

- Intended preview source: current `feat/aws-kubernetes-fullstack`, which includes the website, PostgreSQL path and 100 additional demo products. Baseline `3686ffcde6f3ee52c8862f7fdf433ad3a03aa116` has [successful CI run 41768336373](https://github.com/Vishnu063/Happy_Fatun/actions/runs/41768336373). That old run **does not validate this fix**. The new candidate SHA and its fresh successful run must match and are supplied in the final delivery; the workflow now enforces that match before publication.
- Mismatch origin: both job conditions in `.github/workflows/cloudflare-preview.yml` and `deploymentBranch` in `shared/manual-deployment.ts` still named `feat/furniture-platform`. Changed only those exact source restrictions, description and operator instructions to `feat/aws-kubernetes-fullstack`; repository, environment, Worker and DB names remain fixed. Cloudflare is not currently configured here as a Git-linked branch deployment. No provider source setting was changed.
- Approval gap: the old function accepted any nonempty reviewers array; it did not check admin bypass, selected-branch mode, actual branch policies or malformed reviewers. It accepted the actual insecure policy shape (`can_admins_bypass=true`, no branch policy). The new guard rejects it.
- Enforcement: well-formed User/Team reviewer IDs, one required-reviewers rule with explicit self-review mode, admin bypass explicitly false, selected/custom branch mode, and exactly one explicit **branch** policy for the intended branch. Absent/malformed/truncated/wildcard/tag/old-branch/additional policies fail closed. API/network/JSON failures cannot silently authorize publishing. Sole-owner self-review is allowed only as an explicit setting; this is not two-person review.
- Added exact-commit CI validation via GitHub's CI workflow run metadata: repository, branch, `push` event, workflow path, SHA, completed state and success must all match. Wrong-commit/PR-only/failed/skipped/in-progress runs cannot pass. Confirmed that the API endpoint returns the expected shape for the baseline successful run; final delivery verifies the new candidate independently.
- Workflow guard runs before verification, after the protected environment gate, **and immediately before Wrangler publication** in a shell with `set -euo pipefail`. Actual approval still comes from GitHub's environment gate. Both jobs require the exact repository/ref and check out event SHA; verify has no Cloudflare secret, and only the final publish step receives it. No migrations, secret installation, automatic triggers or approval-skipping fallback were added. This is configuration validation, not proof of a hosted approval decision; privileged repository/provider administrators remain responsible for platform access.
