## Master Control workflow

Sign in to the existing private owner studio, then open **shops & suppliers**. Add a shop; only its name is required. Location, address, phone and shop notes are optional. Link the shop to any existing furniture product. Record optional supplier cost, optional intended selling price, availability, optional lead time and private link notes. Several shops can supply the same product. The products list's **Suppliers for …** action opens a product-filtered view; the existing product editor also includes the same tracking panel. Save a new product before linking suppliers.

Search matches shop, product, location, address, phone and link notes; the directory also searches shop notes. Filter by furniture, shop, location, availability and active/archived/all records. The comparison table orders known costs lowest first and puts missing costs last. Blank costs are NULL, never zero. Gross margin is `(intended selling price − supplier cost) / intended selling price × 100`; missing values or a zero selling price produce “Not calculated”. Costs are integer paise in storage; UI entry is rupees with two decimals. Negative costs, fractions of paise, values above ₹10 lakh and invalid requests are rejected. Confirm equivalent specifications and current terms with the shop; this is an owner record, not an external stock integration.

Edit shop contact details once for all links. Edit link terms independently; these never change the public price, product stock status, quotation snapshots or existing price audit. Archive/restore shops and links rather than deleting sourcing history. An archived shop hides its active links from normal comparison without erasing them; restore the shop before restoring an archived link. Duplicate product/shop links return 409 and direct the owner to edit/restore the existing link. Products with sourcing history cannot be hard-deleted; archive them instead. There are no real or fictional supplier seeds.

## Privacy, data preservation and failure handling

Migration 0010 adds normalized `suppliers` and `product_suppliers` tables with foreign keys and restrictive deletes; it does not recreate products, quotes or authentication tables. All sourcing endpoints are under existing authenticated `/api/admin` middleware, no-store responses, CSRF/origin checks, strict schemas and parameterized SQL. Anonymous access is rejected. Public JSON, server HTML, metadata, sitemap and quotations use explicit public fields and never join supplier contacts, costs or margins. Private values remain in the lazy owner UI/API. Unavailable backend requests display an error and permit reload/retry; a failed save is not shown as success. No third-party supplier service is called.

Before a future approved remote migration, back up and inspect the selected existing D1 database. Check migration history and possible existing category-ID/name conflicts; if migration fails, investigate rather than deleting/resetting records. Migrations 0009/0010 are additive and tested over pre-existing product pricing, quote and session data. Local integration tests also exercise duplicate link races, invalid input, missing/archived references, archive preservation, foreign-key failures and public leakage attempts.
