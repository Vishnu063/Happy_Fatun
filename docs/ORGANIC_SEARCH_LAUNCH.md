# Organic search: implementation and owner launch checklist

Repository SEO is not evidence of Google indexing, traffic or rankings. No #1 position, lead volume or sales is promised. No external account, domain, listing or paid tool was configured during development.

## What the repository provides

- Product and category titles/descriptions have safe defaults. Owner Products → Edit design has optional SEO title (≤70 characters) and meta description (≤180); Categories → Search listing has the same fields, saved with the category action. Blank means defaults. Legacy updates that omit the fields preserve overrides. Search engines may rewrite displayed snippets.
- Gallery descriptions can be edited independently of image bytes, including placeholder images. Save each description in the existing gallery manager. Describe the actual visible furniture/setting, not keyword lists; never describe generic geometry as the real product.
- Sofa, bed, dining, wardrobe and custom-furniture category pages have distinct practical planning guidance and links to their current products, plus measuring/material guides. Archived products are excluded. Empty categories state that no designs are published; they do not imply stock. The server renders useful HTML and links without JavaScript. Current category summaries show up to 100 links; sitemap covers all public product records.
- Two original buying guides live in `shared/content.ts`, used by both React and server HTML. Add/edit a small reviewed entry there, then use the normal review/build/deploy workflow. This is a versioned content capability, **not an admin CMS**. No bulk filler pages were added. Guide routes and the guide index are in the sitemap.
- Product/category canonical URLs, legacy/stale redirects, robots/noindex owner routes, escaped metadata/JSON-LD and safe concept schema remain. All pages use the current request origin until a real domain is configured. Keep one approved public HTTPS host and redirect alternatives at the hosting layer after authorized setup.
- Default Pune geography was removed after the latest owner clarification. Public service-area wording and geographic metadata use only owner-configured facts, otherwise location-neutral wording. An earlier acquisition plan naming a city does not establish a verified service area. No default address, rating, review, history or shipping radius is invented.

## After an explicitly authorized launch

1. Confirm the real service area, contact details, product claims and public HTTPS domain with the owner. Review titles/copy for truthful product differences. Keep approved placeholders labeled until replaced. Verify public pages return 200 HTML, missing/archived pages 404, legacy URLs 301, and owner pages noindex. Do not make private APIs crawlable.
2. The owner creates/selects a Google Search Console property for that domain. Use Google's domain-property DNS verification if they control DNS, or an eligible URL-prefix verification method. Add only the exact verification record/file Google supplies, through an authorized configuration change. Do not guess tokens or publish account credentials.
3. Verify `/robots.txt` references the actual HTTPS `/sitemap.xml`; retrieve the sitemap to confirm XML and current public canonical URLs. Submit that sitemap in the verified Search Console property. This is a request for discovery, not an indexing guarantee.
4. Use URL Inspection on the homepage, each important category, representative products and guides. Check the rendered/crawled HTML, selected canonical, mobile usability and any indexing exclusions. Request indexing only for useful, corrected public pages; do not repeatedly submit thin duplicates. Robots exclusion is not authentication; APIs must retain authorization.
5. Monitor the Pages/indexing report and sitemap status for real errors. Review search queries, impressions, clicks and relevant page engagement over time. Compare actual quoted/won inquiry sources without treating those records as unique visitors or guaranteed orders. No such measurements were collected in this task.
6. Review field Core Web Vitals when enough real data exists, and use throttled mobile tests to investigate slow image loading, layout shifts or heavy 3D use. Local loopback timings do not establish field performance. Optimize actual bottlenecks before adding tools.
7. If eligible, the owner claims/verifies a truthful Google Business Profile through Google's flow. Use only the real business identity and eligible address/service-area model; do not publish a fabricated/virtual address or assume a city. See `LOCAL_ACQUISITION.md` for genuine photos, social presence and permission-based outreach.

Owner inputs still needed: real domain/control, approved business/service-area facts, permitted accurate product content, external account verification, and explicit launch authorization. No paid ads, purchases, production secret entry or external publication is part of this checklist's implementation.
